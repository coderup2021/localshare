# LocalShare 一期开发计划

状态：规划中（2026-11-02）  
目标：交付可在局域网单机部署的 server、user-web、admin-web  
原则：先打通纵向主流程，再扩展功能；每个里程碑以可验证结果结束

## 1. 一期产品基线

### 1.1 MVP 必须完成

- 开发环境 HTTP/WebSocket API 使用 `5678`、Web 入口使用 `7777`；生产环境 API/WS 使用 `8887`、Web 入口使用 `8888`。
- user-web 无需登录，打开即可进入唯一的 public 频道。
- 所有访问者看到同一个 public 消息流，没有单聊、群聊、成员列表或用户目录。
- 文本、图片、视频、普通文件消息。
- 消息历史游标分页、未读数/已读位置、实时新消息。
- 断线重连后历史补齐。
- admin-web 使用唯一管理员 `localShare` 登录，初始密码 `12345678`，支持修改密码。
- 管理员内容软删除、基础系统设置和审计日志。
- 单机部署、数据库迁移、数据库与附件联合备份说明。
- backend 可打包发布到 npm；第三方通过全局安装后的 `localshare` 命令启动、停止和重启服务。
- 首次启动通过 CLI 指定数据目录和本机 IPv4，成功后输出 Web/管理地址及首次默认管理员凭据。

### 1.2 一期明确暂缓

- 单聊、群聊、成员关系及权限系统。
- 普通用户账户、注册、登录和用户管理。
- 多管理员、管理员角色和权限分配。
- 消息撤回、编辑、转发、表情包。
- 桌面端和移动端。
- 公网访问、跨局域网互联、云账号。
- 端到端加密。
- 视频转码、缩略图生成和 CDN。
- 全文检索高级能力和多节点集群。

以上范围属于一期明确边界。若后续加入账户或私聊/群聊，需要重新设计身份、成员关系和对象级授权，不应在一期代码中预埋半成品。

## 2. 执行顺序

```text
M0 工程与决策
  ↓
M1 服务端基础、匿名访客与管理员认证
  ↓
M2 user-web 公共频道与文本消息
  ↓
M3 附件与实时通信（核心纵切）
  ↓
M4 管理后台
  ↓
M5 加固、测试与部署
  ↓
M6 npm 打包、命令管理与发布
```

M3 是关键风险所在。完成 M3 后应进行第一次端到端演示，再决定管理后台细节和体验优化优先级。

CodeGraph 是跨里程碑的强制开发工具：M0 完成仓库根目录初始化，此后每次代码修改前用图谱定位影响面，修改完成后执行 `codegraph sync .` 和 `codegraph status .`，确认图谱无待同步内容。

真实浏览器 E2E 是所有后续代码修改的强制完成门禁。每次修改都必须打开最终 Web 入口，等待应用请求完成，验证关键文案、状态和主要交互，并检查浏览器错误；不能只依赖单元测试、构建或 `curl`。

- 修改密码后旧密码失效，已有管理员会话被撤销。
- 未登录或使用匿名访客 Cookie 访问管理接口时返回 401/403。
- 数据库只保存管理员密码哈希和会话令牌哈希。

## 5. M2 user-web 公共频道与文本消息

### 5.1 交付

- user-web 不包含登录页、注册页、鉴权守卫或用户菜单。
- 首次访问自动初始化匿名访客身份。
- 统一 Axios 客户端、Zod 校验、错误映射和 API base。
- 单个 public 频道页面：消息流、发送文本、加载更早消息和空态。
- Zustand 只保存消息流 UI 状态、草稿和匿名访客展示信息。
- 匿名访客的默认展示名；若提供自定义昵称，仅作为匿名展示名，不是账户。
- 基础响应式布局，桌面与移动浏览器可用。

### 5.2 验收

- 访问 `http://<host>:7777/` 直接进入 public 频道，不发生登录跳转。
- 两个独立浏览器可发送文本并看到同一 public 消息流。
- 消息按服务端 seq 排序，历史分页不重复、不遗漏。
- 请求失败、空频道和加载中有明确状态。
- user-web 不请求管理端接口，不包含管理员会话逻辑。

### 5.3 已完成：public 文本消息纵切

已实现：

- 唯一 public 会话和所有匿名访客可见的文本消息流。
- `POST /api/v1/public/messages` 服务端校验、消息序号和 `(senderType, senderId, clientRequestId)` 幂等约束。
- `GET /api/v1/public/messages` 按 `beforeSeq` 游标分页，结果稳定且不重复。
- user-web 消息列表、发送框、Enter/Shift+Enter、发送状态、错误提示、手动刷新和 3 秒轮询。
- “加载更早消息”与轮询合并去重，加载旧消息时不会强制滚回底部。
- 匿名访客展示名 `访客-XXXX`，自己的消息与其他访问者消息有明确视觉区分。
- 所有能访问 `7777` 的局域网客户端均可发送消息，符合局域网共享目标。
- API 测试覆盖访客 Cookie、未初始化发送拒绝、幂等重放、跨访客可见性和游标分页。
- Chrome E2E 在两个独立浏览器上下文中验证实时可见，并通过本机局域网 IP 实际发送消息。

尚未实现：

- 图片、视频和普通文件。
- 已读位置和未读数。

## 6. M3 附件与实时通信

### 6.1 交付范围

- `messages`、`read_positions`、`attachments` 表及索引。
- 唯一 public 会话的历史消息和幂等发送。
- 图片、视频、文件上传、受控下载、视频 Range。
- WebSocket 公开连接、心跳、public 广播和重连补齐。
- 已读位置、未读数和多标签页去重。
- 客户端消息发送状态：pending/sent/failed/retry。

### 6.2 验收主流程

1. 用户 A 不登录，直接打开 public 频道。
2. A 发送文本，B 在线时实时收到；A 的 HTTP 响应提供权威消息。
3. A 上传图片并发送，B 能预览，刷新后仍可查看。
4. A 上传视频，B 能播放并拖动进度。
5. A 断网后发送失败，恢复网络后可重试且不产生重复消息。
6. B 断线期间 A 连续发送，B 重连后通过 HTTP 补齐，不重复、不丢序。
7. 未登录管理员调用管理接口被拒绝，匿名访客无法获得管理员事件。
8. 超过大小或类型限制的上传被明确拒绝，临时文件被清理。

### 6.3 性能守门

此阶段先建立合理基线，不追求大规模优化：

- 消息列表首屏和历史分页有稳定游标。
- SQLite 查询使用计划中的索引，避免无界全表扫描。
- public 事件只序列化一次，再广播给当前所有有效连接。
- 附件流式处理，不能把大视频完整读入内存。
- 目标规模在部署文档中写明；首版至少以 100 个匿名访客、20 个并发 WebSocket 连接为验收参考。

### 6.4 已完成：WebSocket 实时文本广播

已实现：

- `GET /ws` Bun/Hono WebSocket upgrade，只广播唯一 public 会话事件。
- `ready` 与 `message.created` 稳定事件 envelope，包含 `eventId`、`occurredAt` 和消息 payload。
- HTTP 持久化成功后只广播一次；幂等重放不重复广播。
- 客户端建立 `/ws` 连接、自动指数退避重连，并在每次重连成功后通过 HTTP 拉取最新历史补齐。
- 15 秒 HTTP 轮询仅作为实时连接失效时的兜底。
- 第二个 Chrome 页面在发送前建立实时连接，另一个页面发送后无需等待轮询即可看到消息。
- Hub 单元测试覆盖广播与取消订阅；完整 E2E 继续覆盖本机和局域网 IP 写入。

### 6.5 已完成：图片、视频和文件附件

已实现：

- `attachments` 表、消息附件外键、第四个 Drizzle migration。
- `POST /api/v1/public/uploads` 以原始请求体逐块写盘，限制单文件 100 MB，服务端生成安全存储键并同步计算 SHA-256。
- `POST /api/v1/public/messages` 可携带附件 ID，事务内完成消息写入和附件状态切换。
- `GET /api/v1/public/attachments/:id` 下载已关联附件，支持单段 HTTP Range。
- 可安全内联的栅格图片和常见视频内联展示；SVG 等潜在主动内容强制作为文件下载。
- user-web 使用顶部小图标工具栏选择图片或文件；选择后立即上传并以独立附件消息发送，不在输入框中保留待发送附件。图片和文件支持多选并按顺序发送，文件夹选择暂时关闭。
- 输入框不提供发送按钮，Enter 发送文字、Shift+Enter 换行；上传期间显示当前文件、序号和进度。
- 输入提示可关闭并通过浏览器本地缓存记住偏好；上传进度和错误信息不受提示隐藏影响。
- 消息更新只滚动消息列表到最新位置，不滚动整个页面；支持把文件或图片拖到输入框区域直接发送。
- 聊天图片支持点击灯箱预览、滚轮缩放以及按聊天顺序切换上一张/下一张。
- 图片和文字消息支持右键复制；自己发送的消息支持撤回。撤回状态持久化并通过 WebSocket 同步，撤回后附件不可再下载。
- 公共频道标题下方提供“所有”“图片与视频”“文件列表”三个标签页，分别展示全部消息、媒体附件和非媒体文件附件。
- 分类标签同一行提供滑出式消息搜索；输入停止 500ms 后在服务端数据库搜索消息正文和附件文件名，结果以独立下拉列表展示并可定位到聊天消息。
- 搜索结果下拉使用细轨道和柔和圆角滚动条，滚动时保持列表内容与边界清晰分离。
- 聊天消息列表使用同样收束风格的细滚动条；文件消息使用图标行，图片消息无外层框，文件名仅在悬停或键盘聚焦时从底部浮层显示。
- 输入框支持直接粘贴剪贴板中的图片并立即发送，文字粘贴仍按普通输入处理。
- 输入区不保留内层圆角边框或阴影，图片/文件图标与文本框紧凑排列，状态提示不额外增加分隔线。
- user-web 上传进度、图片预览、视频播放、普通文件下载和附件大小展示。
- 附件消息继续通过 WebSocket 实时广播。
- API 测试覆盖上传、消息引用、下载和字节范围；Chrome E2E 覆盖真实文件选择、发送、实时接收和下载。

## 7. M4 管理后台

### 7.1 交付

- `localShare` 登录页、会话恢复、注销和前端路由守卫。
- 修改密码，成功后要求重新登录并撤销旧管理员会话。
- public 消息列表、检索和软删除。
- 存储使用和孤立附件查看。
- 系统设置：上传限制等。
- 审计日志。
- 高风险操作二次确认。

- 发布安装器不得在 `npm install` 阶段自动启动服务或初始化业务数据库。
- 确定包名、目标操作系统/架构、许可证、npm 仓库、安装运行方式和可复现发布流程。

- 对暂不支持的平台给出明确错误；不提供会在首次启动时静默失败的伪兼容安装。
- 版本升级自动执行向后兼容 migration；升级失败时不得破坏已有数据库和附件。

### 9.2 npm 发布验收

1. 在干净构建环境执行 `npm pack`，检查 tarball 不包含源码测试、`.env`、SQLite、上传文件、日志或本地绝对路径。
2. 从生成的 `.tgz` 全局安装，`localshare --version` 可用，安装过程没有启动服务。
3. 首次执行交互命令，确认默认值为 `~/.localshare` 和 `0.0.0.0`：

   ```bash
   localshare start
   ```

4. 命令仅在 `8887` API/WS 和 `8888` Web 均通过健康检查后报告成功，并打印两个可直接打开的地址；密码仍为默认值时同时打印管理员用户名和 `12345678`。
5. 打开 CLI 输出的 `8888` 地址能直接进入 public 频道并发送消息；打开管理地址能登录。
6. `localshare stop` 返回成功，PID 和两个端口均释放；重复 `stop` 不会误杀其他进程。
7. `localshare restart` 使用保存的数据目录和 IPv4 恢复服务，历史消息、附件和已修改的管理员密码仍有效。
8. `localshare status` 能区分未启动、运行中、状态文件损坏和进程异常退出。
9. 端口冲突、非法 IPv4、非本机 IPv4、不可写数据目录、migration 失败均返回非零退出码和明确错误。
10. 停止服务后安装新版本 npm 包，使用原数据目录重启，migration、消息、附件和管理员登录均正常。
11. 再次 `start` 不重复询问；`restart --reset` 能重新交互指定数据目录和 IPv4。

## 12. 风险登记

| 风险                            | 触发信号                             | 缓解                                                           |
| ------------------------------- | ------------------------------------ | -------------------------------------------------------------- |
| 大文件阻塞进程或耗尽磁盘        | 内存上涨、请求超时、磁盘满           | 流式上传、大小配额、可用空间检查、清理策略                     |
| WebSocket 丢事件                | 客户端状态与服务端历史不一致         | HTTP 为写入真相、seq 游标补洞、幂等合并                        |
| 匿名用户滥用 public 频道        | 刷屏、恶意上传、异常请求量           | 按访客/IP 限流、上传配额、管理员删除和审计                     |
| 管理接口越权                    | 匿名 Cookie 可访问管理 API           | 管理/访客 Cookie 隔离，统一管理员中间件和集成测试              |
| 公开默认密码泄露                | 管理员从未修改 `12345678`            | 首次登录引导改密、登录限流、审计未改密状态                     |
| SQLite 写锁竞争                 | `SQLITE_BUSY`、发送变慢              | WAL、短事务、合理索引、批量已读位置                            |
| `7777/8888` 入口丢失 WS upgrade | 页面可打开但实时更新失败、反复重连   | 开发和生产入口均验证 WebSocket upgrade                         |
| Cookie/CORS 开发生产差异        | 本地可登录、部署后 401               | 开发 `7777`、生产 `8888` 统一同源入口，并做 Cookie 集成测试    |
| 管理操作误伤数据                | 误删消息/附件                        | 软删除、二次确认、审计                                         |
| npm 升级覆盖业务数据            | 数据缺失、附件路径失效               | 强制数据目录与程序目录分离，安装时不初始化数据                 |
| CLI 误杀或重复启动              | stop 杀错进程、双实例争用端口        | 单实例锁、PID + 启动标识、健康检查、幂等 stop                  |
| 监听 IP 不可达                  | 启动成功但局域网无法访问             | 只接受本机 IPv4，成功后打印实际 URL 并做端口可达检查           |
| 发布包缺少运行文件              | 本地能跑、npm 安装后启动失败         | tarball 内容清单、隔离环境全局安装和全生命周期冒烟             |
| CodeGraph 索引落后              | 修改后无法搜索新符号、调用关系错误   | 每次最终代码修改后显式 `sync`，以 CLI `status` 作为完成门禁    |
| CodeGraph 与源码结论冲突        | 图谱结果与当前文件不一致             | 用 `status` 检查新鲜度，必要时 `index` 重建，并以源码/测试为准 |
| 仅用 HTTP/单测代替浏览器验收    | 测试通过但页面白屏、代理或构建错误   | 每次代码修改后运行真实 Chrome/Playwright E2E 并检查控制台      |
| 范围膨胀                        | 单聊、群聊、账户、客户端同时进入一期 | 锁定 MVP，变更必须更新本文档                                   |
